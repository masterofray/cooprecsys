## 1. Choose a model family

Use the model family that matches the operational problem:

| Situation | Recommended starting point |
| --- | --- |
| Sparse implicit user-item interactions | AryColBring |
| Dense representation learning across two entity spaces | Ary2Tower |
| Rich tabular features and query-group ranking | LTR-LightGBM |

## 2. Prepare the interaction data

AryColBring is designed around a sparse interaction matrix. A minimal conceptual shape is:

```python
import numpy as np
import scipy.sparse as sp

interactions = sp.coo_matrix(
    (np.ones(1000), (np.random.randint(0, 100, 1000), np.random.randint(0, 50, 1000))),
    shape=(100, 50),
)
```

The production pipeline can add preparation, encoding, validation, and feature-engineering stages before model training.

## 3. Train AryColBring

The original project usage pattern supports a model configuration such as:

```python
from src.models.arycolbring import AryColBring

model = AryColBring(
    no_components=32,
    loss="warp",
    learning_rate=0.05,
    random_state=42,
)
model.fit(interactions, epochs=10, num_threads=4)
```

## 4. Generate recommendations

The existing README demonstrates score generation for a set of user-item pairs:

```python
user_id = 0
item_scores = model.predict([user_id] * 50, np.arange(50))
top_items = np.argsort(item_scores)[::-1][:10]
```

## 5. Evaluate before deployment

For ranking workflows, evaluate model quality and coverage before production use. The repository contains evaluation utilities under the model packages and tests for initialization, evaluation, data utilities, and cross-validation.

After training, use the report and visualization modules to inspect feature importance, score distributions, rankings, and sample-level explanations. See [Explainability & Dashboards](../explainability/dashboard-overview).
